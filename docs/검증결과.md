# My AI Treasures 구현 검증

검증일: 2026-11-06 (한국 시간). 로컬 Chrome에서 `file://`로 단일 HTML을 실행했습니다.

## 결과

- 계산 엔진: 기획서 기본 예시, 참여자 제외, 결제자가 분담에서 제외된 경우, 행별 세금 반올림, 등록 순서 나머지 배분, 송금 없음, 입력·날짜 검증 통과.
- 2~20명 × 80개 조건 = **1,520개 조합**에서 총지출 = 선결제 합계 = 부담액 합계, 사람별 선결제 + 송금 − 수취 = 부담액 확인.
- UI: 별도 입력·출력 화면, 기본 예시 1,727엔 및 송금 51·473엔, 참여자 제외 후 부담액 759·759·209엔 확인.
- 지출별 0명 선택 차단, 기본 입력 누락의 인라인 안내, 기존 결제자 삭제 방지, 새 참여자의 기존 지출 자동 제외 확인.
- 한국어·영어·일본어 전환과 요청한 브랜드 이름, 번역된 오류·결과, 처음으로 이동 시 한국어 초기화와 입력 유지 확인.
- 새 정산 취소·확인과 통화 유지, 새로고침 시 복원 확인(브라우저 임시 저장 도입 후 정책).
- 정산 안내 텍스트 내용 일치, 클립보드 실패를 재현하여 수동 텍스트와 전체 선택 동작 확인.
- 브라우저에서 외부 HTTP 요청과 JavaScript 오류가 없음을 확인.

## 사용자가 직접 확인할 순서

1. `index.html`을 열고 한국어·영어·일본어를 번갈아 선택합니다.
2. 예시로 둘러보기에서 내역을 확인하고 정산 결과 확인을 누릅니다.
3. 개인 선택을 B·C로 바꿔 송금액 51엔·473엔을 확인합니다.
4. 입력 수정에서 식사 참여자 C를 제외한 뒤 다시 계산합니다.
5. 정산 안내 복사 후 텍스트 편집기에 붙여 넣어 비교합니다.
6. 기기 방향을 돌려 입력이 유지되고 메뉴가 넘치지 않는지 확인합니다.
7. 처음으로, 새 정산 취소·확인을 비교합니다.

사용자 본인의 기획 의도에 대한 최종 승인은 이 자동 검증과 별개입니다.

- 구현 원본·이미지·테스트·검증 기록을 루트로 이동했습니다.
- `python3 build.py`는 루트의 `index.html`을 생성합니다.
- 이동 후 계산 테스트와 8개 화면 크기의 브라우저 검증을 재실행하여 통과했습니다.
- `index.html`만 빈 임시 폴더로 복사하여 내장 배경·로고 표시와 예시 총액 1,727엔을 확인했고, 동반 파일 요청이 없음을 확인했습니다.

## 멤버별 메시지 작성 추가 검증

`tests/member_messages_test.py`로 다음을 확인했습니다.

- 결과의 모든 멤버에게 메시지 작성 버튼 제공.
- 전체 지출·세금·분담·송금 목록과 개인별 요약 포함.
- 기본 예시: A 수취 524엔(B 51엔, C 473엔), B 송금 51엔, C 송금 473엔.
- 차액 0일 때 추가 송금·수취 없음, 재계산 후 변경 금액 반영.
- 메시지 복사 성공, 실패 시 수동 선택, 전체 선택과 Escape 닫기.
- 한국어·영어·일본어와 1440px 데스크톱, 320px 모바일 세로, 844px 모바일 가로에서 대화상자가 화면을 넘지 않음.
- 기존 브라우저 회귀 테스트도 재실행하여 통과.

기획서 완료 기준 20의 구현에 해당합니다. 문자를 자동 발송하지 않으며, 사용자가 생성 문구를 복사해 별도 앱에 붙여 넣습니다.

## 기본 한국어 입력 화면 전환 방지

- 보고된 현상: 언어를 선택하지 않고 시작하기 이후 입력하면 첫 화면으로 복귀.
- 로컬 Chrome의 파일 직접 열기에서 첫 화면 복귀 자체는 재현하지 못했습니다. 다만 입력 중 Enter가 의도치 않게 계산을 실행하는 동작은 확인했습니다.
- 계산을 명시적 버튼 동작으로 한정하고 모든 조작 버튼의 타입을 button으로 지정했습니다. 앱 공통 폼 제출 차단으로 기본 제출에 따른 페이지 재로드를 막습니다.
- 입력칸의 일반 Enter는 화면 전환을 실행하지 않으며, 한글 조합 중 Enter는 조합을 방해하지 않도록 구분합니다.
- `tests/input_navigation_test.py`: 기본 한국어에서 시작하기, 실제 클릭·문자 입력·Enter, 합성 IME 이벤트, 폼 제출 차단, 명시적 계산, 사용자가 의도한 처음으로 동작을 데스크톱·모바일 세로·가로에서 확인했습니다.
- 기존 8개 크기 브라우저 검증과 멤버별 메시지 검증도 통과했습니다. 실제 운영체제 IME와 VS Code 미리보기의 자동 새로고침은 이 검증에 포함되지 않습니다.


## Vercel 준비 및 브라우저 임시 저장

- `vercel.json`: Other 정적 배포, Node 패키징 명령, 출력 `dist`. 필수 환경변수 없음.
- `dist/index.html`만 생성하며 원본 소스·문서를 배포 출력에 복사하지 않습니다.
- 실제 로컬 HTTP 서버에서 일부 입력·결과·언어·선택 멤버의 새로고침 복원, 독립 탭 분리, 새 정산 초기화 유지, 잘못된 저장 내용 무시, 저장 차단 시 메모리 동작을 검증했습니다.
- 8개 크기 반응형·기존 입력·메시지 테스트를 재실행하여 통과했습니다.
- sessionStorage와 향후 Firebase 어댑터의 load/save/clear 계약은 별도 테스트로 확인했습니다. Firebase는 모의 함수로만 검사했으며 실제 DB·SDK·규칙 배포는 수행하지 않았습니다.
- Vercel 실제 배포는 사용자가 새 프로젝트를 생성한 뒤 진행합니다. 현재 확인 범위는 로컬 패키징과 HTTP 브라우저 실행입니다.
